# Example Apps (Binary SDK Consumers)

Both apps consume the SDK exclusively through the binary `Distribution/` SwiftPM
package — they have **no** access to the SDK source. Use them as reference for
integrating the published XCFrameworks.

## Layout

```
Example/
├── SimplePlayer.Native/         # Metal renderer demo
│   └── SimplePlayer.Native.xcodeproj
└── SimplePlayer.TT/             # TTSDK SampleBuffer demo (CocoaPods)
    ├── Podfile
    ├── SimplePlayer.TT.xcodeproj
    └── SimplePlayer.TT.xcworkspace   (generated by `pod install`)
```

Each project's SwiftPM dependency points at `../../Distribution`, which exposes
the binary products:

| Product               | Backed by XCFramework                         |
| --------------------- | --------------------------------------------- |
| `IOSSDKCore`          | `Distribution/xcframeworks/IOSSDKCore.xcframework`         |
| `IOSSDKNative`        | `Distribution/xcframeworks/IOSSDKNative.xcframework`       |
| `IOSSDKSampleBuffer`  | `Distribution/xcframeworks/IOSSDKSampleBuffer.xcframework` |

## Prerequisites

The XCFrameworks must exist on disk before opening either example. From the
repo root:

```bash
./Scripts/build-xcframeworks.sh
```

## Build SimplePlayer.Native

```bash
xcodebuild \
  -project Example/SimplePlayer.Native/SimplePlayer.Native.xcodeproj \
  -scheme SimplePlayer.Native \
  -destination 'generic/platform=iOS Simulator' \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

Or just open `Example/SimplePlayer.Native/SimplePlayer.Native.xcodeproj` in
Xcode and run.

## Build SimplePlayer.TT

CocoaPods needs a one-time install in this directory (the workspace and
`Pods/` are not checked in):

```bash
cd Example/SimplePlayer.TT
pod install
xcodebuild \
  -workspace SimplePlayer.TT.xcworkspace \
  -scheme SimplePlayer.TT \
  -destination 'generic/platform=iOS' \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

> The TT app builds **device-only** (TTSDK ships no simulator slice).

Or open `SimplePlayer.TT.xcworkspace` in Xcode after `pod install` and run on a
connected device.

## Ad-slot jump API

The example UI exposes a row of "Ad #N" buttons (see `PlayerView.swift`)
backed by the public SDK surface:

- `session.allAdSlots: [AdSlot]`
- `AdSlot.adIndex`, `AdSlot.startFrame`, `AdSlot.adProductId`, …
- `session.videoTime(forManifestFrame: Int) -> Double`
- `session.effectiveFPS`, `session.isAdsReady`
- `AdManifestParser.slot(forAdIndex:)`

All of these are visible in the generated `.swiftinterface` files inside each
XCFramework.
